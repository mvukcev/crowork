# UI/UX Visual Pass — 2026-05-17

## Executive Summary

CroWork feels visually ambitious and close to launch quality on public marketing and core listings, with strong typography, gradient identity, and mostly coherent card language. The biggest launch blockers are trust and consistency gaps in authenticated and legal areas: placeholder legal content, untranslated keys in employer forms, role/dashboard route instability, and mixed language strings in worker flows.

Top blockers before beta:
- Legal trust gap: privacy, terms, and cookies pages are placeholder text.
- Translation quality gap: untranslated key strings appear in employer job create flow.
- Platform reliability gap: employer Filament dashboard route throws 500; admin test-login flow throws 500.
- Localization consistency gap: mixed EN/HR strings in worker dashboard/profile completeness chips.
- Mobile header density: authenticated top nav is overloaded at small widths before hamburger use.

## Overall Product Feel

What feels strong:
- Clear brand voice and confident hero typography on Homepage, Jobs, and Educations.
- Good first-screen conversion on Homepage (search + CTA + employer CTA).
- Strong card-based marketplace scanning patterns on listings and pipeline.
- Dark mode visual atmosphere is compelling and differentiating.

What weakens perceived finish:
- Inconsistent quality across product zones (public polished, legal/authenticated reliability weaker).
- Translation and copy governance inconsistencies visible to end users.
- Some dashboard/action routes expose internal errors that reduce trust immediately.

## Critical Visual/UX Issues

1. Placeholder legal pages in production UI
- Affected: `/privacy`, `/terms`, `/cookies`
- Issue: legal pages contain explicit placeholder copy instructing admins to update content.
- Risk: severe trust/compliance perception issue.

2. Untranslated keys in employer create job form
- Affected: `/employer/jobs/create`
- Issue: raw keys shown (for example `ui.jobs.create_heading`, `ui.employer.company_name`, `ui.jobs.full_time`).
- Risk: severe product quality and localization failure.

3. Employer dashboard route instability (500)
- Affected: `/employer` (Filament dashboard)
- Issue: internal server error with missing route for Filament employer resource action.
- Risk: severe reliability and enterprise trust issue.

4. Admin test-login helper instability (500)
- Affected: `/admin/test-login/3`
- Issue: middleware alias resolution error (`Target class [admin] does not exist`).
- Risk: severe QA/admin confidence and staging reliability issue.

5. Mixed-language UI in worker experience
- Affected: `/worker/dashboard` and profile completeness/missing fields block.
- Issue: English headings with Croatian field labels in same panel.
- Risk: severe localization coherence problem for multilingual launch.

## Medium Priority Issues

1. Authenticated mobile header overload
- Buttons (language/theme/notifications/dashboard/logout/hamburger) are all visible at narrow width.
- Reduces tap clarity and hierarchy before opening menu.

2. Employer create/edit forms feel dense and long
- Strong data model coverage but low chunking and weak progressive disclosure.
- Conversion friction for first-time employer posting.

3. CTA hierarchy drifts between surfaces
- Public pages: consistent and strong.
- Authenticated pages: occasional equal-weight secondary actions create decision friction.

4. Error pages are visually clean but context-light
- 403/404 pages do not always show role-aware next best actions.

## Low Priority Polish

1. Spacing rhythm is mostly good but can tighten in long forms and dashboard data sections.
2. Some metadata text sizes are slightly low-contrast in dark mode.
3. Cookie banner visual weight competes with content on first load.
4. Filter controls on listings could align label-input vertical rhythm more tightly.

## Mobile Findings

Key findings:
- Mobile visual quality is strong in dark mode hero surfaces.
- Authenticated header remains crowded (many top actions visible simultaneously).
- Hamburger menu itself is good and comprehensive once opened.
- Pipeline/table views need mobile-friendly fallback patterns to avoid horizontal scan fatigue.
- Form-heavy pages (employer create/edit, worker profile) need stronger sectioning for thumb-scroll ergonomics.

## Dark Mode Findings

Key findings:
- Brand atmosphere is very strong and differentiating in dark mode.
- Headline contrast remains high and readable.
- Some secondary metadata text can drift toward low-contrast gray.
- Menu overlay in dark mode is functional and visually coherent.
- Error page in dark mode looks polished, but context help and role-aware recovery could improve.

## Localization Findings

Key findings:
- Mixed EN/HR content appears in worker dashboard completeness/missing-field area.
- Employer create flow displays raw untranslated keys (critical).
- Overall public marketing content appears mostly consistent in English during pass.
- Locale switching UI is present and discoverable in header and mobile menu.

## Conversion Findings

What supports conversion well:
- Homepage immediate search + role bifurcation CTA.
- Worker empty states provide clear next actions.
- Employer pipeline and candidate controls support active hiring workflows.

What blocks conversion:
- Trust-critical legal placeholders.
- Broken employer root dashboard route.
- Employer create-form translation defects reduce confidence at key conversion step.
- Long forms without progressive disclosure increase completion drop risk.

## Component Consistency Findings

Consistent:
- Brand typography style in public hero sections.
- Card treatment and pill/chip language across core marketplace pages.
- General spacing and border radius system in many areas.

Inconsistent:
- Public premium shell vs utility-style auth forms.
- Mixed label languages within a single role dashboard context.
- Some dashboard/table/form surfaces still feel legacy versus newer card-shell standards.
- Authenticated top nav behavior differs from expected compact-mobile pattern.

## Recommended Fix Plan

### Quick Wins

- Replace legal placeholder copy on `/privacy`, `/terms`, `/cookies`.
- Fix untranslated keys in `/employer/jobs/create`.
- Force-role safe redirect from `/employer` failure state to `/employer/dashboard` until route issue is fully resolved.
- Normalize mixed-language chips/labels in worker dashboard to active locale.
- Reduce cookie banner initial prominence on auth screens.

### Medium Fixes

- Rework authenticated mobile header to reduce visible top-action clutter.
- Add responsive card mode for employer pipeline table on mobile.
- Segment employer create/edit forms into collapsible or tabbed sections.
- Align forgot/reset auth shell visual language with access page and public brand styling.
- Improve dashboard section separators and KPI readability in employer dashboard.

### Larger UX Improvements

- Introduce consistent cross-role dashboard design language with shared spacing, card hierarchy, and action patterns.
- Add trust framework content blocks (SLA/support/legal status/profile verification cues) across contact/about/employer onboarding.
- Build localization QA guardrails for mixed-language and missing-key regressions before release.

## Suggested Execution Order

1. Resolve critical trust/reliability blockers: legal placeholders, employer root 500, untranslated create-job keys.
2. Fix localization coherence in worker/employer user-critical flows.
3. Improve authenticated mobile header and table/form mobile usability.
4. Standardize auth-shell and dashboard visual consistency.
5. Apply broader conversion and trust signal enhancements.
